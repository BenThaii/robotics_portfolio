From teacher rollouts to a deployable interface

The policy does not replace the physics stack — it sits on top of it: a 50 Hz head over the same 500 Hz torque loop.

01

The teacher

500 Hz torque PD with the pelvis assist, unchanged from project 02. It is both the data source and the yardstick — teacher mode is bit-for-bit identical to the physics run.

02

The interface

362-dim deployment-shaped observation, one action every 20 ms, dq bounded ±0.35 rad around the reference. The PD law runs inside every 500 Hz sim step.

03

The network

Analytic PD head plus a residual MLP — 473k parameters. The head is filled from the deployed law, so at dq=0 the network is the controller by construction.

04

The export

ONNX graph 1.85 MB, runtime parity 3.6e-8 against PyTorch, 0.062 ms per single-observation inference on CPU — 322× inside the 20 ms budget.

Joint RMSE through the same metric function used for the teacher · simulation only

Nobody falls anywhere in the robustness grid — mass ±20%, floor friction 0.7–1.3, motor strength ±10%, sensor noise ×4 — and every push up to 500 N is recovered by teacher, dq=0 and the PPO student alike. The pelvis assist dominates; that is the honest reading.

Why the residual has nothing to learn: the PD head already is the controller, and the assist already balances. A joint-level residual is not the missing piece of this stack.

Honest scope — what this is NOT

Simulation only — no hardware in the loop and no sim-to-real claim. The free base still falls at 0.43 s without the pelvis assist: the assist is doing the balancing, not the network. Joint RMSE is the only claim here; task success is not measured.
