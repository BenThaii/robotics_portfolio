RGB-D SLAM and navigation on a real mobile robot

Project: RTAB-Map RGB-D SLAM on a Kobuki base, then Nav2 navigation on the map the robot just built. This is real hardware, not simulation. Demo: https://benthaii.github.io/robotics_portfolio/mobile-robot/

1. What was built

An eight-phase self-directed program (P0.1–P0.8): workstation setup → Gazebo bring-up (topics, TF, camera, LiDAR, ros2 bag) → SLAM with slam_toolbox + AMCL → Nav2 autonomous navigation → RGB-D perception and LiDAR fusion → inspection-mission capstone → real-robot deployment → RGB-D SLAM with RTAB-Map on the real robot.

This report covers the final hardware stage; earlier stages were simulation.

2. Hardware and stack

  • Base: Kobuki (TurtleBot2-class)
  • Compute: Jetson Xavier NX, ROS 2 Foxy (matched to the robot)
  • Sensors: Intel RealSense D435 (RGB-D, colour-aligned), RPLiDAR A3
  • SLAM: RTAB-Map 0.21.1 — RGB-D, pose graph, loop closure
  • Navigation: Nav2 on the RTAB-Map occupancy grid
  • Geometry check: custom depth-anchored bundle adjustment (offline, on the recorded bags)
  • Simulation twin: ROS 2 Jazzy + Gazebo, map_server + AMCL + Nav2

3. Pipeline

sensors (D435 depth/colour, A3 scan, wheel odom)
  → TF + optical-frame convention
  → RTAB-Map RGB-D odometry + local/global loop closure
  → pose-graph optimization                 → corrected trajectory + 3-D cloud
  → occupancy grid (depth → ray tracing)   → Nav2 costmaps
  → Nav2 goals                              → guarded drives with safety stops
  → (offline) depth-anchored bundle adjustment → map geometry verified against the measurements

4. Engineering work that mattered

Sensor-frame bug found from the point cloud alone. A custom RealSense publisher stamped optical-convention pixels with a non-optical, identity-rotated TF frame. RTAB-Map silently projected the whole room 0.7–3.6 m overhead. Diagnosed from the cloud's z-distribution (a level camera at 0.5 m cannot see above ~1.6 m), fixed with the standard optical-frame convention (rpy −90°/0/−90°), verified end to end: cloud flattened to 0–1.7 m and became floor-dominated; grid extent grew ~60%.

Cross-version compatibility. RTAB-Map parameter/topic/QoS names were checked against the Foxy release source before running. Two version-default traps caught: Grid/RayTracing false in 0.21.1 vs true in 0.23.13, and QoS defaults (Reliable vs best_effort publishers).

Safety layering. Front-scan obstacle stop, bumper panic-stop, 0.6 s command watchdog, and odometry-integrated (not timed) motion commands. Three guarded drives completed with zero collisions.

Predict-then-run discipline. Every drive had a written expected observation; surprises became numbered findings with root causes. Failure modes were compared across sim and real — the textureless sim rejected all 19 global loop closure hypotheses (≈134 word matches but <20 geometric inliers — texture starvation), while the textured real room accepted them freely (97 and 24 global links in the day-one dbs' Link tables).

5. Results

OBSERVED, read from the RTAB-Map pose-graph database and the final Nav2 run.

metric value
accepted loop-closure links, final session (proximity, db Link table) 174 (17 more in a second session)
keyframes, final session 4,041 (second session added 4,893)
wheel-odometry drift corrected by pose-graph optimization 0.75 m
mapped occupancy grid 10.1 × 9.7 m, 5 cm cells
final Nav2 goal error 7.1 cm
fused coloured voxels 72,643 at 5 cm, from 1.6M RGB-D points
collisions across 3 guarded drives 0

A Gazebo twin loads the saved map into map_server + AMCL and runs Nav2 through five waypoints in a pillar field: 5/5 waypoints reached. This is simulation, reproducible from the repo, not hardware.

The depth anchor then moved from the twin to hardware. A recorded drive — two laps of the room so every wall gets re-observed — feeds a custom depth-anchored bundle adjustment on the same RGB-D observations: 27,755 trimmed observations, reprojection RMSE 0.326 → 0.219 px, 99.9% of observations within 10% of measured depth (median 0.25%), trajectory within 3.1 cm RMS of the RTAB-Map optimized poses. A second drive runs the full 4-mode ablation: anchored BA keeps 99.7% of measured depth, fully free BA 21% — free wins reprojection by 0.04 px while warping the room; the anchor buys a metric map for 0.04 px. RTAB-Map's optimized poses are the reference in both tests, not independent ground truth. The full result — explainer video, annotated procedure drive and ablation figures — has its own page: depth-anchored BA.

6. Honest scope

  • Real hardware: the map, fused cloud, Nav2 goal error and the depth-anchored BA results (two recorded drives). Simulation: the waypoint mission and the p08 structure-from-motion ablation. Labelled separately throughout.
  • This is a learning rig — not a product, no users, no fleet.
  • Self-directed program — no employer, title or dates attached. AI coding agents wrote substantial code under the author's direction; the verifiable contribution is program design, execution, verification and debugging.
