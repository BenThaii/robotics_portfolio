Technical report · 02 / 05

Retargeted motion under physics (G1, MuJoCo)

Project: Execute retargeted G1 trajectories with explicit joint torques in MuJoCo, and report the truth about what joint-level control can and cannot do. Demo: https://benthaii.github.io/robotics_portfolio/motion-physics/ Scope: simulation only. No physical G1 was driven.

1. Question

The retargeting project produces kinematically feasible trajectories. This project asks the next question: are they physically trackable? Both retargeting flavours are tested — Stage 1 (own IK, 23-DoF reference with six model-only joints held at zero) and Stage 2 (GMR, 29-DoF, every hinge referenced).

2. Controller

All 29 hinge joints are driven by explicit joint-space torque PD with gravity-compensation feedforward:

tau = kp · (q_des − q) + kd · (qd_des − qd) + gravcomp · qfrc_bias
kp = 300, kd = 8, gravcomp = 1

Nothing else drives a joint. The free base is unactuated: no RL, no MPC, no ZMP, no whole-body controller. When the robot diverges, that is a result (time-to-divergence), not something hidden.

The "assisted" runs substitute a soft pelvis workspace PD (600 N/m linear, 200 Nm/rad angular) as a stand-in for a balance controller. It does not drive any joint. It is documented, tunable (--base-kp 0 disables it) and ramps in over the first second.

3. Making an IK model simulatable

GMR's g1_mocap_29dof.xml is an IK-grade model, never meant to be stepped. build_scene.py converts it into a simulation scene:

  1. Mesh self-collision off. Convexified hulls of adjacent-but-one links overlap around shared joints; MuJoCo only auto-excludes direct parent/child pairs, and the contact solver detonated at step one.
  2. Planar sole patches instead of four r=5 mm point contacts per foot. The points rocked and chattered under 34 kg — contact count flickered 7→0 in 20 ms and kicked the robot over.
  3. One nameless template motor dropped. A motor with default transmission 0 silently double-drove left_hip_pitch. The 29 real motors are torque motors with unlimited ctrlrange, as a PD wants.

At load time, track_pd.py adds hinge armature (0.01) and damping (1.0) for numerical stiffness, settles 0.5 s at the start pose, and repairs the reference: a centered median filter (--median 5) removes 1-frame IK chatter, and joint velocity is saturated at 12 rad/s (--vmax 12) to remove frame-0 cold-start discontinuities (a median cannot fix a single endpoint jump).

4. Results

OBSERVED, 2026-11-15, from recorded run outputs and metrics JSONs.

run reference duration joint RMSE mean/worst (rad) base pos RMSE result
box_full Stage 1 IK 46.6 s / 1399 frames 0.150 / 0.54 0.16 m tracked to end, never fell
box_gmr_full Stage 2 GMR 46.6 s / 1399 frames 0.245 / 0.62 0.21 m tracked to end, never fell
walk_15s Stage 1 IK 15 s / 450 frames 0.086 / 0.35 0.18 m tracked, incl. footsteps
walk_gmr_15s Stage 2 GMR 15 s 0.173 / 0.42 0.15 m tracked, incl. footsteps
box_freebase Stage 1 IK 0.43 s 0.045 / 0.13 — fell at 0.43 s

Both retargeting pipelines produce physically trackable trajectories. GMR references track with ~60% higher joint RMSE than Stage 1 IK on the same clip (0.245 vs 0.150 rad on box), consistent with GMR's higher retargeting error under its own rotation-weighted yardstick. The two RMSE figures use different targets and are never compared head-to-head.

5. The free-base ablation is the point

With the base assist off, joint tracking is still good at 0.045 rad mean — and the robot topples in 0.43 s. Joint-level torque control alone does not balance a humanoid. Balance and locomotion need a separate controller on top. This is reported as a deliberate result, not a failure of the retargeting.

6. Live retargeting

A fresh 38.3 s CMU basketball BVH (subject 13, 1149 frames @ 120 Hz), never in any config, was retargeted through the exact GMR stage at ~380–550 FPS instantaneous (mean ~380–425) on CPU, single process — a real terminal capture, with a rendered human | G1 comparison (whole-body RMSE 16.2 cm on this dynamic clip).

7. Honest scope / limits

  • Simulation only — no real-hardware G1 operation is claimed.
  • The soft pelvis PD replaces balance/locomotion; no RL, MPC, ZMP or WBC.
  • On Stage 1 IK-reference runs, waist_pitch/roll and wrist_pitch/yaw (the six joints the 23-DoF IK model lacks) are held at zero — the upper body is slightly stiffer than the human's. GMR-reference runs reference all 29 and do not have this caveat.
  • Reference base-attitude RMSE (~23° on box) reflects feet not exactly where the human's were; base pose is not presented as accurate.
  • GMR is external work (Araújo et al., Stanford, ICRA 2026, MIT).

8. Reproduce

cd projects/g1-physics-tracking
conda run -n motion-retargeting python scripts/dump_ik_trajectory.py --clips walk box
conda run -n g1-physics python scripts/build_scene.py
MUJOCO_GL=egl conda run -n g1-physics python scripts/track_pd.py \
  --clip box --frames 0 --render output/box_full_sbs.mp4 \
  --out output/box_full_metrics.json
# free-base divergence:
MUJOCO_GL=egl conda run -n g1-physics python scripts/track_pd.py \
  --clip box --frames 90 --base-kp 0 --base-kd 0 --base-kpang 0 --base-kdang 0
