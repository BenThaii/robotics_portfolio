C++ port — bounded differential IK / retargeting

A dependency-free C++17 port of the core algorithm from projects/humanoid-motion-retargeting/src/motion_retargeting/. It exists as concrete C++ evidence for robotics roles that ask for C++ (NVIDIA, EngineAI, Meituan), not as a replacement for the Python pipeline.

What is ported, exactly

Python source C++ header What it does
ik.py — RetargetIK include/retarget_ik/ik.hpp log-parameterised freeflyer, weighted residual stack, pelvis yaw via log3, posture regulariser, exact box bounds on actuated joints, warm start, two-bone arm target rebuild
retarget.py include/retarget_ik/retarget.hpp BVH→robot axis map (x,y,z)→(z,x,y), per-limb proportion matching, arm segment lengths/directions, ground alignment, pelvis yaw from hip rotation
bvh.py (model layer) include/retarget_ik/chain.hpp floating-base serial-chain FK with joint origins, axes, limits and named frames

The three Python unit tests in tests/test_ik.py (reachable target, joint limits, yaw task) are ported one-for-one in tests/test_retarget_ik.cpp.

Honest scope

  • Not a Pinocchio port. The chain FK covers only what the residual uses (frame positions/rotations). It does not parse the G1 URDF or load meshes. The unit-test two-link chain is the same URDF used by the Python tests.
  • Solver difference. Python calls scipy least_squares(method="trf") with finite-difference Jacobians. This port uses the same residual and bounds with a damped least-squares (Levenberg–Marquardt) loop and box projection. Same bounded differential-IK formulation; not bit-identical to scipy TRF.
  • No BVH parser. BVH parsing stays in Python. This port starts at parsed keypoint positions and optionally hip rotations.
  • Kinematics only — no dynamics, balance, contact or torque limits.

Cross-check against the original Python solver

tests/crosscheck_python.py runs the same two-link cases through the original scipy/Pinocchio implementation (requires the motion-retargeting conda env):

conda run -n motion-retargeting --no-capture-output python tests/crosscheck_python.py

Observed 2026-11-16:

case Python q_act C++ q_act task error (Python / C++)
reachable (0.020247, 1.348982) (0.020247, 1.348982) 0 / 0
yaw 0.7 (0, −0) (0, −0) 0 / 0
unreachable (limit) (0.365762, 1.500000) (0.280254, 1.500000) 0.2475 / 0.2228

The reachable and yaw cases match exactly. The unreachable case has no unique solution: both solvers park joint 2 on its +1.5 rad limit (saturated = 1), but TRF and damped least squares settle at different joint-1 values. This is the expected consequence of the solver difference above, not a discrepancy in the residual or bounds.

Build and run

cd portfolio_docs/cpp
make            # builds build/retarget_cli and build/test_retarget_ik
make test       # runs the ported unit tests
make run        # CLI demo + target-builder demo

Or with CMake:

cmake -S . -B build-cmake
cmake --build build-cmake
ctest --test-dir build-cmake --output-on-failure

Requires only a C++17 compiler (g++ or clang++). No Eigen, Pinocchio, scipy or ROS needed.
